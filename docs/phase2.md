# Phase 2: RGB-D認識からアプローチ姿勢へ

## 到達点

固定カメラでMuJoCoシーンのRGB画像と深度画像を取得し、赤いブロックを画像上で検出する。検出画素を3Dワールド座標へ変換し、ブロックの10 cm上に手先を移動するためのアプローチ姿勢と関節角を生成する。

```bash
./scripts/run_vision_demo.sh
```

結果は`outputs/phase2/`へ出力される。

- `rgb_detection.png`: 検出枠と中心点を描いた画像
- `detection.json`: 画素座標、3D座標、アプローチ姿勢、関節角

認識結果を使って、アプローチ、降下、把持、持ち上げまで実行する。

```bash
./scripts/run_grasp_demo.sh
```

GUIなしで自動評価だけを実行する場合:

```bash
./scripts/run_grasp_demo.sh --headless
```

`outputs/phase2/grasp_result.json`には、ブロックの初期・最終高さ、持ち上げ距離、
指との接触数、成功判定が保存される。成功条件は5 cm以上の持ち上げと、最終状態で
少なくとも1件のfinger contactがあること。

## 処理パイプライン

1. `workspace_camera`から整列済みRGB・深度画像をレンダリングする
2. RGBチャンネル比による明示的なルールで赤色領域を抽出する
3. 対象画素の深度をピンホールカメラモデルで3D点群へ変換する
4. 点群の中央値をブロック位置として採用する
5. ブロック上方へ安全距離を持つアプローチ姿勢を作る
6. Phase 1の逆運動学で関節角へ変換する
7. elbow-up姿勢で上方から接近し、指を閉じて15 cm上方へ持ち上げる
8. ブロック高さと接触情報から把持成功を判定する

## なぜ最初は色検出なのか

Phase 2の目的は、画像、カメラ座標、ワールド座標、ロボット制御の接続を理解すること。決定論的な色検出を基準実装にすることで、Phase 4以降の学習モデルと精度・失敗条件を比較できる。

## 実装上のポイント

- 同じ手先姿勢にも複数のIK解がある。把持ではテーブル下から接近する解を避け、
  `elbow_up=True`を使う
- GUIモードではシミュレーション時間に合わせて描画を待機し、動作を観察可能にする

## 次の課題

- ブロック位置、照明、カメラノイズをランダム化する
- 色以外の特徴を使う物体検出へ置き換える
- 複数の把持候補を評価し、失敗時に再試行する
